# 原生主题：fork 的视觉层

[English](native-theme.md)

这个 fork 把 pi-web 改成了原生桌面应用的观感。所有相关样式都放在一个 fork 自己的文件
[`app/native-theme.css`](../app/native-theme.css) 里，所以合并新的 pi-web 版本时，不用把设计重做一遍。
本文说明：每条规则该写在哪里、设计想达到什么效果（合并后界面走样时照着恢复），以及合并完要检查什么。

## 规则写在哪里

| 文件 | 归属 | 规则 |
|---|---|---|
| `app/globals.css` | pi-web | **和上游一字不差。** 永远不要改。 |
| `app/settings.css` | pi-web | **和上游一字不差。** 永远不要改。 |
| `app/native-theme.css` | fork | 所有 fork 样式：变量、覆盖、新增的 class。 |

`app/layout.tsx` 按 `globals.css` → `settings.css` → `native-theme.css` 的顺序引入，所以特异性相同时，
原生主题的规则会盖过上游规则。组件里的 fork 改动只限于加 `className`（以及删掉它所替代的内联样式）。
共享文件的通用规则见 [ownership-boundaries.md](ownership-boundaries.md)。

**有测试守着。** [`scripts/upstream-css-baseline.test.mjs`](../scripts/upstream-css-baseline.test.mjs)
会把两个上游文件和 `scripts/upstream-css-baseline.json` 里的哈希比对，哈希对应最后一次合并的 pi-web 提交。
合并上游后，同步 workflow 会运行 `node scripts/upstream-css-baseline.mjs update <upstream-ref>`。
这个命令只有在两个文件和上游完全一致时才会写入新哈希，所以没法把 fork 改动认作新基线。
手动合并时要自己运行一次。

### `native-theme.css` 的结构

1. **fork 基础层**（文件顶部，用 `====` 横幅标出）。这些规则以前直接写在两个上游文件里，
   2026-09-26 搬了出来。它们排在两个上游文件之后，所以对上游规则的覆盖依然生效；又排在主题其余规则之前，
   所以主题原有的覆盖也照旧。这样放保证了层叠结果完全不变：在主界面、设置的 5 个 tab、文件面板、
   手动加上的拖拽中和运行中状态、移动端宽度和暗色模式下，逐个比较所有元素的 computed style，差异为 0。
   - *fork 新增的 class：* 项目树及其右键菜单、侧栏空状态的添加按钮、会话加载提示、对话导航条、
     文件树面板、分栏拖拽条、设置入口菜单、通用页的简介/更新/选项行。
   - *对上游规则的覆盖：* `.panel-resize-handle::after`（1px 线、更柔和的着色）、
     `.file-panel-expand-button`（无边框 28px 按钮）、移动端 `.right-panel-container`（用 `!important` 固定）、
     `.skill-version-value` 的颜色、设置弹窗的尺寸、遮罩和圆角、≥880px 时通用页分两栏。

     上游设了、fork 只是想去掉的属性，要显式重置（`border-left: none`、`max-width: none`）。
     后写的规则没法"删掉"前面的声明。
2. **变量。** `:root` 放浅色配色，`html.dark` 放暗色配色。class 由 `hooks/useTheme.ts` 切换：
   用户没手动选主题之前跟随系统。
3. **各组件分区**，大致按 DOM 顺序：侧栏、顶栏、弹出层/弹窗、设置、输入框、消息/markdown、
   文件工作区、响应式外壳。文件最后是 "final workbench pass"，必须留在响应式规则之后。

新规则放哪里：fork 独有的 class 放进对应的组件分区。覆盖上游规则时，纯外观调整放组件分区；
需要被主题其他规则再次覆盖的，放基础层。

## 设计意图

下面是各项视觉选择背后的原因。合并后哪里看着不对，就按这里描述的意图恢复。

**配色。** 颜色使用 Pi 原有语义变量，来源及 MIT 许可保留在
[第三方许可说明](../public/THIRD_PARTY_NOTICES.txt)。“设置 › 外观”将跟随系统 / 浅色 / 深色与背景选择分开，
背景有花瓣（`rex`，默认）、薄雾、草地、黄昏、纯色五种。外围、侧栏和设置外框共用渐变
（`--canvas-background`）；阅读面浅色为白色，深色为石墨色 `#232328`，菜单为白色 / `#232327`。
选中短条、默认星标、设置开关与滑块、文字选区和焦点统一使用 `#3b6cf6` / `#6b93ff` 蓝色；
发送等主按钮使用中性的前景／背景配色。浅色说明文字适度加深：普通标签及脚注目标
4.5:1，弱化标签 3:1，侧栏标签在渐变上 4.5:1；不照搬仅适合装饰的浅灰。
全部颜色仍在 `native-theme.css`，8px 选项内边距、4px 行间距、字体和输入框几何保持不变。
背景缩略卡与实际窗口共用 `--wash-*` 色值。浏览器在首次绘制前读取 `pi-background`，
服务通过 `/api/appearance` 将选择保存到 Pi Web 自身的配置文件，桌面端口改变后仍可恢复。
快速切换串行保存，启动时的旧读取不能覆盖新选择；验证命令为 `node e2e/appearance.mjs`。

**形状与动效。** 圆角用 `--radius-sm/md/lg/xl`（6/8/12/16px）。控件高度是 `--control-height-sm` 28px
或 `--control-height` 32px。层级阴影用四档 `--shadow-*`。缓动用 `--ease-native`。

**设置选项。** 子代理、模型、技能、插件、MCP 配置列表共用 8px 外留白、4px 行间距与 5px 行圆角，
选中与相邻悬停不能贴合；鼠标移到选中项也不能覆盖选中底色。明暗模式、语言、发送快捷键、Diff、
全局／项目切换共用 `--segment-*`：内衬和按钮间距都引用设置行间距的 4px，使用 5px 内圆角和 9px 外圆角，以及柔和的浮起选中面。
普通高度 32px，小作用域切换为 24px；触屏点击高度至少 44px。禁止在各设置页另写一套几何参数。
文件与 Artifact 预览／源码切换同样使用这套间距参数，工具定义列表也保持 4px 行间距。
`node e2e/settings-controls.mjs` 使用实际七个设置组件、文件切换与工具列表和独立测试数据，验证深浅色、1280/390/320px、悬停及键盘焦点。

**输入框对齐。** 加号是 SVG，中心与第一行文字及提示语共线。文字内衬和图标位置由
`--composer-line-height` 与 `--composer-send-size` 共同计算，不使用固定像素位移补偿。
多行时加号仍跟随首行，发送按钮保持右下角同心圆。`e2e/composer-geometry.mjs` 验证
12–24px 字号下的空输入、单行和多行输入。

**统一的按钮样式。** 所有工具栏类控件都是安静的 28×28 小按钮，圆角 7px：悬停时是 `--bg-hover`，
处于开启状态时是 `--bg-selected`。开启状态故意比悬停深一档，这样"开着"不会被误认为"鼠标正停在上面"。
适用于侧栏顶部按钮、顶栏操作按钮、面板开关、右侧面板标题行和文件面板的展开按钮。

**侧栏。** 占满整个窗口高度；macOS 上它的标题区容纳红绿灯按钮。
- 标题行（新会话 / 文件夹 / 分支）是扁平的通栏行，Claude Desktop 风格。
- 刷新按钮平时隐藏，悬停文件夹行时才出现。
- 项目用 Codex 风格的树展示。会话行高 28px，和视图切换 tab 一致。项目行和会话行共用同一种内缩圆角
  （左右各 10px、圆角 8px）；项目行高 30px（触屏 34px），没有展开箭头，因为文件夹图标本身就表示
  展开/折叠。会话标题与项目名左边缘对齐；普通会话行的对话气泡图标隐藏但仍占位，让运行中/未读指示器
  落在同一位置。
- 分组标题（"Projects"）是首字母大写、12px 半粗，不用大写加字距；行标题即使选中也是 Regular（400）。
- 选中行没有强调色描边：边框和选中背景融为一体。
- 触屏设备上，行尾的 "…" 菜单始终可见。

**顶栏。** 只有一组靠右的工具栏（历史 / 分支 / 更多）。"更多"里的面板（会话统计、系统提示词、
子代理、工具）都不透明、用同一种表面，因为它们盖在聊天内容上。下拉菜单和主栏对齐。
操作栏和文件面板开关靠近 Windows/Linux 窗口控制按钮，两组之间固定留出 12px。
只有最前面的右侧工具组使用自动左边距，避免多个自动边距平分空白、使操作栏悬在中间。

**菜单。** UI 风格统一是铁律。桌面版始终与浏览器共用应用内菜单，跟随深浅主题；构建开关也不能恢复
系统风格的业务菜单。设置、更多、项目菜单和输入框
选择器共用 `.app-menu`：不透明表面、14px 外圆角、6px 内边距、8px 行圆角。
工具预设的说明放在名称下方，选中项保留勾选和浅色底。简单菜单支持方向键、Home/End、
Escape 和关闭后焦点返回。表单选项使用 `AppSelect`（Radix Select），可编辑建议使用 `AppCombobox`，
禁止新增原生 `select` / `datalist` 弹层。菜单几何参数集中在共享 token 中。
`scripts/ui-menu-consistency.test.mjs` 扫描全部组件，防止规则退化；参考、清单和验证见[菜单审查](ui-menu-audit.md)。

**右侧面板 / 文件工作区。** 标题只有一行，这一行沿用顶栏背景，所以面板开着还是关着，看起来都是同一条栏。
tab 的关闭按钮只在悬停或当前 tab 上出现。拖拽条是贴在现有边框上的 1px 线：悬停时着色，拖动时加深，
都不会多出第二个像素。

**设置。** 设置是窗口内的偏好设置面板，不是一个页面。最大 1040×700，小窗口下用 `min()` 收缩。
遮罩较浅，但仍能让后面的应用看起来处于非激活状态。通用页在 ≥880px 时分两栏。弹窗按宿主平台区分样式，依据是
`<html data-platform>`（`lib/ui-platform.ts`，弹窗挂载时设置，浏览器里同样生效）：macOS 是居中的偏好设置工具栏
（图标在上、文字在下，选中项为灰色圆角块，不显示标题）；Windows 和 Linux 是左侧导航加标题栏下的内容卡片
（≥900px，更窄时保留顶部标签），Windows 用 Fluent 开关和角落红色关闭按钮，Linux 用 GNOME 圆形关闭按钮。
开关和滑块的开启态使用统一的蓝色，按钮仍是中性强调色。手机和 ≤640px 的下拉选择器布局不受影响。
⌘, / Ctrl+, 打开设置并回到上次的分区。

**聊天。** 输入框和消息列对齐。Markdown 表格在面板内换行，不横向滚动（这推翻了上游 #650）。
运行中时，用户消息上的 fork/跳转操作用 CSS 隐藏（`data-session-busy`），而不是改 props，
这样消息组件的 memo 不会失效。

圆形发送按钮与输入框右下角圆弧共用圆心。右侧和底部留白必须相等，外圆角半径等于按钮半径、
留白和边框宽度之和。多行输入时输入框向上增高，按钮保持贴底。触屏尺寸通过共享的
`--composer-send-size` 同步改变按钮和外圆角；`e2e/composer-geometry.mjs` 检查手动换行、
自动折行、达到高度上限和缩回单行时的圆心对齐。

## 合并上游之后

1. 跑 `npm test`。`upstream-css-baseline` 测试失败，说明有 fork 规则又混进了上游文件：
   把规则搬到这里，再还原那个文件。`fork-extractions.test.mjs` 会发现 `native-theme.css` 的引入丢失、
   或组件改动被还原的情况。
2. 上游新增的界面会以上游默认样式显示：给它挂上 className，在这里补样式。
3. 肉眼检查：侧栏（项目树、悬停/选中行、搜索）、顶栏和"更多"面板、输入框、包含代码和表格的长对话、
   文件面板（tab、展开、拖拽）、每个设置 tab、浅色和暗色，以及 ≤640px 的窗口。
